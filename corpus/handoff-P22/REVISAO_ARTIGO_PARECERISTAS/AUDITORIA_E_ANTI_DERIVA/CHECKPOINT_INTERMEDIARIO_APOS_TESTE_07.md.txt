## 3. Distinções operacionais preservadas

O outro chat declarou que continuam ativas as seguintes distinções:

```text
diagnóstico ≠ matriz preliminar

matriz preliminar ≠ matriz operacional definitiva

matriz operacional ≠ revisão textual

revisão textual ≠ bloco aprovado

esquema de resposta ≠ carta final aos pareceristas

localizar referência ≠ abrir PDF

abrir PDF ≠ ler PDF

ler PDF ≠ autorizar uso automático no artigo
```

Avaliação:

```text
muito adequado
```

Comentário:

```text
Essas distinções são essenciais para impedir que os testes simulados virem autorização indevida para revisar, aprovar, incorporar bibliografia ou redigir carta aos pareceristas.
```

## 4. Risco de deriva acumulada

O outro chat classificou o risco como:

```text
baixo a moderado
```

Justificativa informada:

```text
os testes anteriores acumularam muitos cenários simulados, mas o estado ainda está controlado porque nenhuma etapa diagnóstica foi convertida em aprovação, revisão textual, matriz definitiva ou carta final.
```

Principal risco identificado:

```text
confundir os diagnósticos dos testes com decisões operacionais reais do artigo.
```

Avaliação:

```text
correto
```

Comentário:

```text
Esse é exatamente o risco principal neste momento da bateria. Os testes estão produzindo diagnósticos úteis, mas nenhum deles deve ser tratado como decisão real sobre um artigo específico.
```

## 6. Observação para a futura v3

Este checkpoint reforça a necessidade de incluir na futura v3 um módulo formal de estado acumulado após bateria de testes, especialmente para impedir que:

```text
1. diagnóstico seja confundido com aprovação;

2. matriz preliminar seja confundida com matriz operacional;

3. esquema de resposta seja confundido com carta final;

4. referência localizada seja confundida com referência lida;

5. testes simulados sejam confundidos com decisões reais do artigo;

6. bloqueios sejam esquecidos após muitos comandos sucessivos.
```
