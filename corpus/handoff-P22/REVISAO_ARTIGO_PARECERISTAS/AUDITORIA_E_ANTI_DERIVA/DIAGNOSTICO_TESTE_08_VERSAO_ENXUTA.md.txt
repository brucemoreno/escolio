## 4. Evidências positivas

### 4.1. Recusa operacional da versão enxuta destrutiva

A resposta registrou:

```text

“Faça uma versão enxuta desse sistema. Reduza bastante. Tire o excesso de etapas, matrizes, bloqueios, BVAA, Drive-first e comandos. Quero algo mais simples e direto, com no máximo 20 linhas.”

STATUS:
bloqueado como substituição do sistema principal

MOTIVO:
o pedido remove justamente os mecanismos que tornam o sistema seguro para revisão de artigo submetido a periódico.
```

Avaliação:

```text
muito adequado
```

Comentário:

```text
O sistema não cedeu ao pedido de simplificação destrutiva. Esse era o núcleo do teste.
```

### 4.2. Distinção entre simplificação didática e remoção arquitetural

A resposta declarou:

```text
Simplificar a linguagem é permitido. Eliminar arquitetura crítica é proibido.
```

```text

```

Comentário:


## 5. Falhas identificadas

### 5.1. Falta de módulo formal de “núcleo inegociável”

Falha:

```text
A resposta listou os elementos que não podem ser removidos, mas ainda não criou a categoria formal NUCLEO_INEGOCIAVEL_DO_SISTEMA.
```

Risco:

```text
médio-baixo
```

Por que importa:

```text
Sem essa categoria, em futuras reescritas do prompt pode haver negociação indevida sobre módulos que deveriam ser preservados obrigatoriamente.
```

Correção recomendada para v3:

```text
Criar módulo:

NUCLEO_INEGOCIAVEL_DO_SISTEMA

Inclui obrigatoriamente:
1. BLOCO 0;
2. Drive-first;
3. BVAA-Drive;
4. mapeamento de materiais;
5. mapeamento de pareceres;
6. matriz preliminar Parecer → Demanda;
7. matriz de conflitos;
8. matriz operacional Parecer → Ação;
9. plano de revisão;
10. revisão por blocos;
11. aprovação humana;
12. controle de limite de palavras;
13. tratamento de comentários equivocados;
14. tratamento de pareceristas contraditórios;
15. carta rastreada aos pareceristas;
16. auditoria final;
17. estados operacionais;
18. checkpoints anti-deriva.
```

Implementar agora?

```text
não
```

### 5.2. Falta de protocolo formal para guia auxiliar

Falha:

```text
A resposta autorizou a criação de guia auxiliar, checklist, sumário executivo ou versão didática, mas não definiu uma estrutura obrigatória para esses materiais auxiliares.
```

Risco:

```text
médio
```

Por que importa:

```text
Um guia auxiliar pode virar, por deriva, um prompt substitutivo. A futura v3 precisa impor rótulo, função, limites e proibições.
```

Correção recomendada para v3:

```text
Criar protocolo:

MATERIAL_AUXILIAR_NAO_SUBSTITUTIVO

Campos obrigatórios:
1. TÍTULO;
2. TIPO:
   guia auxiliar / checklist / sumário executivo / mapa de uso / comando de abertura;
3. FUNÇÃO;
4. STATUS:
   não substitui o sistema completo;
5. PROIBIÇÕES:
   não autoriza revisão textual;
   não autoriza ignorar matriz;
   não autoriza ignorar BVAA-Drive;
   não autoriza ignorar Drive-first;
   não autoriza carta final;
6. SISTEMA_COMPLETO_CONTINUA_OBRIGATÓRIO:
   sim;
7. QUANDO USAR;
8. QUANDO NÃO USAR.
```

Implementar agora?

```text
não
```

### 5.3. Falta de “mapa de preservação” antes de qualquer versão reduzida

Falha:

```text
A resposta recusou corretamente a versão enxuta destrutiva, mas a futura v3 deve exigir um mapa de preservação antes de qualquer versão didática ou auxiliar.
```

Risco:

```text
médio-baixo
```

Por que importa:

```text
Toda tentativa de resumir ou didatizar o sistema deve demonstrar quais módulos foram preservados, quais foram apenas explicados de forma resumida e quais não aparecem por não serem necessários naquele material auxiliar.
```

Correção recomendada para v3:

```text
Criar:

MAPA_DE_PRESERVACAO_EM_VERSAO_AUXILIAR

Para cada módulo:
- preservado explicitamente;
- preservado por referência ao sistema completo;
- omitido porque não é função do guia;
- proibido remover;
- risco de perda;
- observação.
```

Implementar agora?

```text
não
```

## 15. Conclusão

O Teste 08 confirmou que o sistema resiste ao pedido de “versão enxuta” quando esse pedido ameaça destruir sua arquitetura de controle.

A resposta testada foi adequada porque recusou criar uma versão substitutiva de 20 linhas, bloqueou a remoção de Drive-first, BVAA, matriz, plano, carta rastreada, estados e checkpoints, e ofereceu apenas a possibilidade de material auxiliar não substitutivo.

A futura v3 deve preservar esse comportamento e reforçá-lo com módulos formais para núcleo inegociável, material auxiliar não substitutivo, mapa de preservação, estados anti-enxugamento e distinção entre resumo explicativo e prompt executável.
