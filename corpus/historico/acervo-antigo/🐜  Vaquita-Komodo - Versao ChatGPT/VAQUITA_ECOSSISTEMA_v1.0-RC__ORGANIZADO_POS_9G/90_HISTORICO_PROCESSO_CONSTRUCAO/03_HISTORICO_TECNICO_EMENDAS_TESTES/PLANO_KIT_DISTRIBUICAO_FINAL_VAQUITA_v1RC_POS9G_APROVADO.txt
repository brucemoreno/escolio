PLANO DE KIT DE DISTRIBUIÇÃO FINAL — ECOSSISTEMA VAQUITA v1.0-RC — PÓS-9.G

## 1. VEREDITO

**PLANO APROVÁVEL**

ANTI-DERIVA AQUI: este plano não gera arquivos, não altera documentos, não declara v1.0 final e não inicia o kit. Ele apenas define a estrutura segura para uma futura geração controlada.

## 2. OBJETIVO DO KIT

O kit de distribuição final pós-9.G deve reunir, em estrutura limpa e operacional, os arquivos necessários para instalar, carregar, usar, migrar e auditar o Ecossistema Vaquita v1.0-RC após a aprovação técnica da FASE 9.G.

O kit deve servir para:

1. uso operacional real do ecossistema;
2. instalação em novos chats;
3. preservação dos documentos-mãe vigentes;
4. separação clara entre arquivos ativos e histórico técnico;
5. prevenção de drift por versões antigas;
6. rastreabilidade da equivalência entre nomes curtos operacionais e nomes longos históricos.

O kit **não** deve declarar versão v1.0 final. Ele deve ser tratado como **kit de distribuição pós-9.G / v1.0-RC**, ainda anterior à eventual decisão humana sobre v1.0 final.

## 4. ARQUIVOS OBRIGATÓRIOS

Devem entrar obrigatoriamente no kit:

### 4.1. Documentos-mãe pós-9.G ativos

```text
01_KIT_MESTRE_VAQ_ECO_v1RC_POS9G_FINAL.txt
02_INSTAL_USO_VAQ_ECO_v1RC_POS9G_FINAL.txt
03_MIGRACAO_VAQ_ECO_v1RC_POS9G_FINAL.txt
```

Esses são os nomes operacionais canônicos. Os nomes longos devem aparecer apenas na tabela de equivalência, não como nomes principais de uso.

### 4.2. Prompts operacionais vigentes

```text
VAQUITA_ORQUESTRADOR_v1.0-RC__PROMPT_OPERACIONAL_CONSOLIDADO_AUDITADO.txt
BOOTSTRAP_CARREGAMENTO_VAQUITA_v1.0-RC.txt

KOMODO_v1.0-RC__PROMPT_OPERACIONAL_AUDITADO.txt
BOOTSTRAP_CARREGAMENTO_KOMODO_v1.0-RC.txt

BVAA_v1.0-RC__PROMPT_OPERACIONAL_AUDITADO.txt

JARARACA_v1.0-RC__PROMPT_OPERACIONAL_AUDITADO.txt

HANDOFF_v1.0-RC__PROMPT_OPERACIONAL_CONSOLIDADO_AUDITADO.txt
```

### 4.3. Manifestos obrigatórios

```text
README_COMECE_AQUI.txt
MANIFESTO_ARQUIVOS_VIGENTES.txt
TABELA_EQUIVALENCIA_NOMES.txt
```

Esses três arquivos devem deixar inequívoco:

1. quais arquivos usar;
2. quais arquivos não usar como vigentes;
3. qual é a correspondência entre nomes curtos e nomes longos;
4. que a FASE 9.G está aprovada tecnicamente;
5. que isso ainda não equivale a v1.0 final.

## 5. ARQUIVOS OPCIONAIS

Podem entrar, desde que separados dos ativos:

1. kits de uso rápido;
2. especificações funcionais dos módulos;
3. relatórios de auditoria;
4. testes mínimos de regressão;
5. emendas históricas;
6. versões anteriores pós-9.F, pós-9.E e R4.3.

A regra é: materiais opcionais podem entrar apenas se estiverem claramente em `02_APOIO` ou `03_HISTORICO_AUDITORIA`.

As versões anteriores, se incluídas, devem ficar apenas em:

```text
99_VERSOES_ANTERIORES_NAO_USAR/
```

e devem conter aviso explícito:

```text
NÃO USAR COMO VERSÃO VIGENTE.
PRESERVADO APENAS PARA RASTREABILIDADE HISTÓRICA.
```

## 6. ARQUIVOS QUE NÃO DEVEM ENTRAR

Para reduzir risco de drift, não devem entrar no kit operacional principal:

1. duplicatas com nomes longos dos três documentos-mãe, salvo se ficarem em histórico;
2. versões intermediárias com sufixos `CORRIGIDO`, `INTERDOC`, `REFCHECK`, `ARQUIVO_CONFIRMADO` como arquivos operacionais;
3. arquivos pós-9.F tratados como vigentes;
4. arquivos pós-9.E tratados como vigentes;
5. prompts experimentais não auditados;
6. pacotes de teste parciais sem marcação histórica;
7. rascunhos de auditoria não consolidados;
8. qualquer arquivo cujo status não esteja claro;
9. qualquer arquivo que possa sugerir que P030, Daston/Park, UR-30, Capítulo 3 ou seção 3.2 são regras universais.

A regra prática: se um arquivo pode confundir “vigente” com “histórico”, ele não deve ficar na raiz nem em `00_ATIVOS_POS_9G`.

## 7. MANIFESTO / README RECOMENDADO

O kit deve conter um `README_COMECE_AQUI.txt` curto e operacional.

Conteúdo recomendado:

```text
README_COMECE_AQUI — ECOSSISTEMA VAQUITA v1.0-RC — PÓS-9.G

1. Use primeiro a pasta 00_ATIVOS_POS_9G.
2. Para instalar o ecossistema, consulte 02_INSTAL_USO_VAQ_ECO_v1RC_POS9G_FINAL.txt.
3. Para compreender a arquitetura completa, consulte 01_KIT_MESTRE_VAQ_ECO_v1RC_POS9G_FINAL.txt.
4. Para migrar ou retomar desenvolvimento em novo chat, consulte 03_MIGRACAO_VAQ_ECO_v1RC_POS9G_FINAL.txt.
5. Os prompts operacionais vigentes estão em 01_PROMPTS_OPERACIONAIS_VIGENTES.
6. Arquivos em 03_HISTORICO_AUDITORIA e 99_VERSOES_ANTERIORES_NAO_USAR não devem ser usados como vigentes.
7. A FASE 9.G está tecnicamente aprovada.
8. Este kit ainda não declara versão v1.0 final.
```

O `MANIFESTO_ARQUIVOS_VIGENTES.txt` deve listar apenas os arquivos operacionais atuais.

O `TABELA_EQUIVALENCIA_NOMES.txt` deve registrar os nomes longos apenas como origem/histórico.

## 9. RISCOS ANTI-DERIVA

Riscos a monitorar:

1. usar arquivo histórico como vigente;
2. reintroduzir documentos pós-9.F como ativos;
3. confundir nomes longos de verificação com nomes operacionais;
4. criar novos sufixos após `POS9G_FINAL`;
5. transformar FASE 9.G em v1.0 final sem decisão humana;
6. misturar funções de Vaquita, Komodo, BVAA, Jararaca e Handoff;
7. transformar Handoff em auditor;
8. transformar BVAA em revisor textual;
9. transformar Komodo em verificador bibliográfico;
10. transformar Jararaca em corretor de parágrafo;
11. suavizar `CORRIGIR_ANTES_DE_AVANÇAR`;
12. suavizar `PENDENTE_BVAA`;
13. suavizar `PEDIR_PDF`;
14. transformar `ESTRUTURA_ESTÁVEL_COM_RESSALVAS` em autorização automática;
15. universalizar P030, P029, P028, UR-30, Capítulo 3, seção 3.2 ou Daston/Park.

## 10. CHECKLIST ANTES DE GERAR O KIT

Antes de gerar qualquer ZIP ou pasta final, verificar:

1. Os três arquivos curtos existem e correspondem às versões longas congeladas.
2. Não há nomes longos usados como operacionais principais.
3. A pasta `00_ATIVOS_POS_9G` contém apenas os três documentos-mãe curtos.
4. A pasta `01_PROMPTS_OPERACIONAIS_VIGENTES` contém apenas prompts operacionais vigentes.
5. Handoff vigente é o consolidado:
   `HANDOFF_v1.0-RC__PROMPT_OPERACIONAL_CONSOLIDADO_AUDITADO.txt`.
6. Emendas históricas, se incluídas, estão apenas em histórico.
7. Versões pós-9.F/pós-9.E/R4.3, se incluídas, estão em `99_VERSOES_ANTERIORES_NAO_USAR`.
8. O README declara que o kit é pós-9.G, mas ainda não é v1.0 final.
9. O manifesto lista nomes curtos como canônicos.
10. A tabela de equivalência registra nomes longos apenas como rastreabilidade.
11. Nenhum arquivo operacional declara que o teste completo ainda está pendente.
12. Nenhum arquivo operacional declara que o Pacote de Migração ainda está pendente.
13. Nenhum arquivo transforma caso de teste em regra universal.
14. Nenhum arquivo mistura funções dos módulos.
