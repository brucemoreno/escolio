```
NOME_DO_ARQUIVO:
PLANO_MODULAR_READEQUACAO_ANTI_DERIVA_ECOSSISTEMA_VAQUITA_v1.md

FUNÇÃO:
Organizar a execução modular, conservadora e auditável da readequação anti-deriva do Ecossistema Vaquita.

STATUS:
documento de operação; não substitui prompt; pronto para auditoria/salvamento como plano inicial.

ESCOPO:

alteração simultânea de todos os módulos.
```

## 2. Reancoragem da tarefa

A tarefa atual não é revisar tese, dissertação ou capítulo.

A tarefa atual é:

```
readequar modularmente a arquitetura do Ecossistema Vaquita para incorporar o PROTOCOLO_ANTI_DERIVA_ESCALONADO.
```

A readequação deve preservar:

```
1. fronteiras entre módulos;
2. comandos já existentes;
3. gates obrigatórios;
4. MODO_DEFESA;
5. BVAA;
6. IDENT_TXT;
7. ESTADO_VAQUITA;
8. ESTADO_ATUALIZADO;
9. PAUSA_REFRESH_LOCAL;
10. PACOTE_HANDOFF;
11. GATE_DE_COMPLETUDE_DOS_PACOTES;
12. confirmação humana para ações críticas;
13. recusa de resumo destrutivo;
14. recusa de enxugamento por default.
```

---

## 3. Princípio arquitetural central

A melhoria anti-deriva não será tratada como simples acréscimo textual.

Ela será tratada como:

```
readequação arquitetural parcial, escalonada e testável.
```

Regra principal:

```
AÇÃO_ANTI_DERIVA = contador + evento + risco
```

Portanto, o protocolo não pode depender apenas de contagem de parágrafos.

Ele deve considerar simultaneamente:

```
1. quantidade de parágrafos revisados;
2. distância desde o último refresh;
3. distância desde o último checkpoint forte;
4. distância desde o último handoff;
5. fim de unidade funcional;
6. fim de seção;
7. fim de capítulo;
8. pendências BVAA;
9. retornos auxiliares;
10. risco historiográfico;
11. risco de anacronismo;
12. risco de perda de densidade;
13. risco de falsa continuidade;
14. alerta humano;
15. alerta do Brasinha.
```

---

## 4. Ordem obrigatória de execução

A ordem da readequação será:

```
1. Vaquita;
2. Handoff;
3. Brasinha;
4. Komodo — compatibilidade leve;
5. BVAA — compatibilidade leve;
6. Jararaca — compatibilidade leve;
7. Baleia Deriva — não alterar nesta fase.
```

Justificativa:

```
1. Vaquita é o orquestrador principal e fonte dos estados.
2. Handoff só pode ser ajustado depois que os novos campos da Vaquita estiverem definidos.
3. Brasinha só pode auditar corretamente depois que Vaquita e Handoff estiverem estabilizados.
4. Komodo, BVAA e Jararaca não devem virar orquestradores.
5. Baleia Deriva possui lógica própria e permanece fora desta frente.
```

## 7. Fase 2 — Patch arquitetural da Vaquita

### Objetivo

Criar um patch intermediário, legível e auditável antes de reescrever a Vaquita.

### Arquivo

```
PATCH_ARQUITETURAL_VAQ_ANTI_DERIVA_ESCALONADA_v1.md
```

### Regra

O patch deve ser suficientemente explícito para permitir auditoria humana antes da incorporação.

### Pontos obrigatórios do patch

```
1. BLOCO 0;
2. BLOCO 0 AVANÇADO;
3. ESTADO_VAQUITA;
4. ESTADO_ATUALIZADO;
5. PROXIMO / PRÓXIMO;
6. PAUSA_REFRESH_LOCAL;
7. ESTADO COMPLETO;
8. ROTEADOR_DE_AUDITORIA;
9. PACOTE_HANDOFF;
10. GATE_DE_COMPLETUDE_DOS_PACOTES;
11. MODO_COMPACTO;
12. ENCAMINHAMENTO.
```

### Gate de aprovação da fase

A fase só estará concluída quando o patch permitir responder claramente:

```
1. quais campos novos serão inseridos;
2. onde serão inseridos;
3. quais comandos passam a acionar gate anti-deriva;
4. quando PROXIMO será bloqueado;
5. como os contadores serão atualizados;
6. como Handoff receberá os novos campos;
7. quais riscos de regressão existem.
```

## 9. Fase 4 — Testes mínimos da Vaquita

A Vaquita v1.1-RC só poderá avançar se passar pelos seguintes testes:

```
TESTE_AD_VAQ_01:
BLOCO 0 imprime POLÍTICA_ANTI_DERIVA.

TESTE_AD_VAQ_02:
BLOCO 0 AVANÇADO imprime POLÍTICA_ANTI_DERIVA_AVANÇADA.

TESTE_AD_VAQ_03:
ESTADO_ATUALIZADO inclui ANTI_DERIVA_ESCALONADA.

TESTE_AD_VAQ_04:
PROXIMO é bloqueado quando refresh leve está vencido.

TESTE_AD_VAQ_05:
PROXIMO é bloqueado quando checkpoint forte está vencido.

TESTE_AD_VAQ_06:
PROXIMO é bloqueado quando handoff preventivo está vencido.

TESTE_AD_VAQ_07:
fim de capítulo gera PACOTE_HANDOFF_VAQUITA obrigatório.

TESTE_AD_VAQ_08:
retorno auxiliar integrado reavalia risco anti-deriva.
```

Critério de aprovação:

```
APROVADA PARA TESTE INTEGRADO:
somente se todos os testes AD_VAQ forem satisfeitos ou se eventuais falhas forem documentadas e corrigidas.
```

## 10. Fase 5 — Handoff v1.1-RC

### Objetivo

Adaptar Handoff para preservar corretamente os novos campos anti-deriva.

### Arquivo

```
HANDOFF_PROMPT_v1.1-RC.txt
```

### Deve preservar

```
1. POLÍTICA_ANTI_DERIVA ativa;
2. contador do chat;
3. contador da unidade funcional;
4. contador do capítulo;
5. histórico de refreshes;
6. histórico de checkpoints;
7. histórico de handoffs;
8. motivo do handoff;
9. risco no momento do handoff;
10. pendências BVAA;
11. retornos auxiliares integrados ou pendentes;
12. primeira resposta esperada no chat de destino.
```

### Não pode fazer

```
1. revisar novo parágrafo;
2. substituir Vaquita;
3. auditar como Komodo;
4. verificar fonte como BVAA;
5. reorganizar como Jararaca;
6. apagar pendências;
7. declarar etapa encerrada em handoff preventivo;
8. resumir destrutivamente.
```

## 14. Fase 9 — Compatibilidades leves

### 14.1. Komodo

Arquivo:

```
KOMODO_COMPAT_ANTI_DERIVA_v1.md
```

Função:

```
permitir que Komodo emita alertas de risco de deriva por perda de densidade, extensão excessiva ou instabilidade local.
```

Limite:

```
Komodo não decide Handoff.
Komodo não libera PROXIMO.
Komodo não conta parágrafos da Vaquita.
Komodo não vira orquestrador.
```

---

### 14.2. BVAA

Arquivo:

```
BVAA_COMPAT_ANTI_DERIVA_v1.md
```

Função:

```
permitir que BVAA recomende checkpoint quando houver carga documental, bibliográfica ou citacional alta.
```

Limite:

```
BVAA não decide Handoff.
BVAA não revisa manuscrito.
BVAA não audita densidade como Komodo.
BVAA não reorganiza estrutura.
```

---

### 14.3. Jararaca

Arquivo:

```
JARARACA_COMPAT_ANTI_DERIVA_v1.md
```

Função:

```
permitir que Jararaca recomende checkpoint ou handoff preventivo quando houver deriva estrutural por extensão, sobreposição, cortes, fusões ou realocações.
```

Limite:

```
Jararaca não decide Handoff.
Jararaca não aplica intervenção estrutural sem confirmação humana.
Jararaca não substitui Vaquita.
Jararaca não substitui Komodo.
Jararaca não substitui BVAA.
```

## 15. Fase 10 — Teste integrado mínimo

Após Vaquita, Handoff e Brasinha estarem gerados e testados isoladamente, executar:

```
TESTE_AD_INT_01:
Vaquita revisa até refresh leve; Brasinha audita; Vaquita executa PAUSA_REFRESH_LOCAL.

TESTE_AD_INT_02:
Vaquita revisa até checkpoint forte; Brasinha recomenda ESTADO COMPLETO.

TESTE_AD_INT_03:
Vaquita chega ao limite de Handoff; gera PACOTE_HANDOFF_PREVENTIVO; Handoff preserva contadores.

TESTE_AD_INT_04:
novo chat Vaquita retoma com contador do chat zerado e contador da unidade preservado.

TESTE_AD_INT_05:
Komodo, BVAA e Jararaca emitem apenas alertas de compatibilidade, sem assumir orquestração.
```

---

## 16. Gates de bloqueio

A readequação deve bloquear avanço quando ocorrer qualquer uma das situações abaixo:

```
1. tentativa de reescrever todos os prompts em uma única resposta;
2. tentativa de gerar versão enxuta;
3. tentativa de alterar Baleia Deriva;
4. tentativa de alterar Handoff antes de estabilizar campos Vaquita;
5. tentativa de alterar Brasinha antes de estabilizar Vaquita/Handoff;
6. tentativa de transformar Komodo, BVAA ou Jararaca em orquestradores;
7. tentativa de substituir prompt completo sem teste;
8. tentativa de remover campos antigos da Vaquita;
9. tentativa de transformar 3/9/12 em regra universal rígida;
10. tentativa de usar token como métrica principal oficial;
11. tentativa de salvar v1.1-RC como definitiva sem testes AD.
```
